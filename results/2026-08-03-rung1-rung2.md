# Rung 1 vs rung 2, 2026-08-03

## Setup

- **Device under test**: AMD Ryzen 7 9800X3D (8 cores / 16 threads), 62 GB RAM,
  Windows 11 Pro build 26200, .NET 10.0.302. NIC: Realtek PCIe 2.5GbE Family
  Controller, driver 1125.26.50.2025, linked at 1 Gbps.
- **Generator and sink**: NAS on the same switch, running `udpbench serve` in a
  container with host networking. Runs triggered over the HTTP control API.
- **Traffic**: 32-byte UDP payloads (78 bytes on the wire), one destination, so
  every received packet is forwarded exactly once.
- **Each data point**: 10 s measured, preceded by a discarded 3 s warmup against
  the same forwarder process, 4 sender threads.
- **Loss**: sender count vs sink count, both reported by the control API.
- **CPU**: forwarder process CPU seconds over the run, as a percentage of one
  core (the forwarders are single-threaded).

## Harness ceilings

Measured before the rungs, because a harness that cannot outrun the thing it
measures produces fiction:

| Component            | Ceiling      | Notes                                    |
| -------------------- | ------------ | ---------------------------------------- |
| Generator (16 thr)   | ~540,000 pps | ~42% of 1 GbE line rate at this size     |
| Sink                 | ~400,000 pps | single-threaded receive loop             |

Both sit well above the rungs measured here. They will not be enough for rungs
3 and up.

## Reading

Rung 2 eliminates the per-datagram garbage (432 B to 72 B at 32 bytes, 1600 B to
72 B at 1200 bytes, and no Gen0 collections at all) and this buys 2-4% of
per-operation time and nothing measurable in throughput or CPU. Both rungs carry
roughly 150,000 pps cleanly, both start losing packets around 175,000, and both
peg a single core at about 90% doing it.

The syscall pair dominates: roughly 4 us per datagram either way. Allocation was
never the bottleneck at this rate, so removing it could not move the number.

## Caveats

- The device under test was not otherwise idle (no fixed power plan, no core
  pinning). Repeat runs vary by a percent or two, visible in the non-monotonic
  loss figures around the cliff.
- Micro-benchmark timings cover a loopback send plus receive, not wire
  performance; only the allocation columns transfer to the LAN setting.
